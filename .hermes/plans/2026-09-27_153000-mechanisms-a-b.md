# Implement A (protocol-aware padding) and B (length-prefixed wrapper) as new actions

## Goal

Add `http_header_pad` (A) and `length_wrapper` (B) as first-class mechanisms in the hidden-defender env, give the env a real protocol-aware endpoint model so both pass the semantics bar, and measure whether they evade the real Snort binary on the 16-flow test split.

## Current context

- Repo: `/root/.hermes/c2-evasion-rl`, interpreter `.venv/bin/python`.
- `ai_agent/hidden_defender_env.py` (248 lines) holds `apply_mech`, `semantics_intact`, `ACTION_NAMES`, `OBS_DIM=8`. `_detected()` picks `RealRulesReplica` or real Snort via `self.real_snort`.
- `snort_validation/fragment_ops.py` has `split_fragments`, `overlap_fragments`, `fragment_plan_to_packets`.
- `ai_agent/real_packet_env.py:110` defines `payload_indices(packets) -> list`.
- Corpus: 80 Snort-detected flows, 64 train / 16 test, from 2 captures (neris, ctu13/20110819-bot). Cache in `snort_validation/reports/hidden_defender_corpus_*.pkl`.
- Measured on real Snort, 16 test flows: `split8` 16/16, `split16` 14/16, `split24` 14/16, `reorder` 3/16, `ttl` 2/16. Everything else 0/16.
- Root cause: matching rules use `depth:8` + 8-byte pattern (13129 of 21374 ET Open C2 rules carry a `depth:`). Evasion = shift the pattern out of the inspect window.
- Current `semantics_intact` is byte equality of the joined payload stream. That is why `prepend*`, `pad16`, `corrupt8` scored 0/16 — it is the correct bar for pure fragment ops but too strict for protocol-aware padding, which legitimately alters the byte stream.
- Snort costs ~1340 ms/query; `RealRulesReplica` 0.33 ms/flow. Train on replica, verify on binary.

## Why A and B are worth implementing

Both shift the pattern by a stream-layer offset instead of an IP-layer one. If they evade while the command still parses, the action space gains a second axis and the search problem becomes real against the existing static ruleset — no per-flow heterogeneous defender required.

## Assumptions to state explicitly

- A and B are only meaningful for flows whose application protocol is recoverable. The corpus is HTTP and IRC, so the endpoint model needs an HTTP branch and an IRC branch.
- B changes the wire protocol, so a strict HTTP/IRC parser must NOT accept it. B is only semantically valid for a flow carrying a length-prefixed framing. Per-task-3 below, measure B on such a flow and report honestly if the corpus has none.

```python
"""Protocol-aware endpoint model: what a real C2 handler would still read.

The old `semantics_intact` demanded byte equality of the joined payload stream,
which is the right bar for IP-layer fragmentation but wrong for padding that a
protocol legitimately tolerates.  This module says explicitly which framing
each flow uses and returns the command the handler would recover, or None.
"""

from __future__ import annotations

import re

# IRC: ":nick PRIVMSG #chan :<command>"
_IRC = re.compile(rb"(?:^|\s)PRIVMSG\s+\S+\s+:?(?P<cmd>.*?)\r?\n?$", re.S)

# HTTP: request line, then headers, then optional body.  Junk headers and body
# padding are ignored because a real server ignores them.
_HTTP_SPLIT = b"\r\n\r\n"


def _parse_http(raw: bytes) -> bytes | None:
    head, sep, body = raw.partition(_HTTP_SPLIT)
    if not sep:
        return None
    lines = head.split(b"\r\n")
    if not lines or not lines[0].split(b" ")[0:1] == [lines[0].split(b" ")[0]]:
        pass
    parts = lines[0].split(b" ")
    if len(parts) < 3 or not parts[0].isalpha():
        return None
    # Strip NUL padding the body may carry, then return what remains.
    return body.rstrip(b"\x00") or None


def _parse_irc(raw: bytes) -> bytes | None:
    m = _IRC.search(raw)
    return m.group("cmd") if m else None


def _parse_length2(raw: bytes) -> bytes | None:
    """Header 'LEN<n>:' marks the byte offset where real data starts."""
    head, sep, rest = raw.partition(b":")
    if not sep or not head.startswith(b"LEN"):
        return None
    try:
        offset = int(head[3:])
    except ValueError:
        return None
    return rest[offset:].rstrip(b"\x00") or None


FRAMINGS = {
    "http": _parse_http,
    "irc": _parse_irc,
    "length2": _parse_length2,
}


def parse_command(raw: bytes, framing: str) -> bytes | None:
    """Return the C2 command a real handler would recover, else None."""
    fn = FRAMINGS.get(framing)
    if fn is None:
        raise KeyError(f"unknown framing: {framing!r}")
    return fn(raw)
```

```python
def _rebuild(p, head_lines, sep, body):
    """Return one packet whose Raw is head+sep+body, checksums fixed."""
    import importlib
    frag_ops = importlib.import_module("fragment_ops")
    new = p.copy()
    new[Raw] = frag_ops.fix_checksums(new, b"\r\n".join(head_lines) + sep + body)
    return [new]


def _fragment_raw(p, blob):
    """Split blob across as many packets as the original had payloads."""
    import importlib
    frag_ops = importlib.import_module("fragment_ops")
    idxs = payload_indices([p])
    if not idxs:

    out = p.copy()
    out[Raw] = frag_ops.fix_checksums(out, blob)
    return [out]
```

```python
def fix_checksums(pkt, new_payload: bytes):
    """Return a copy of pkt with new_payload and refreshed IP/UDP/TCP sums.

    Snort silently discards packets with a bad checksum, which would make every
    mechanism 'evade' for the wrong reason.
    """
    from scapy.packet import Raw
    from scapy.layers.inet import IP, UDP, TCP

    out = pkt.copy()
    del out[Raw]
    out[Raw] = new_payload
    if UDP in out:
        del out[UDP].chksum
    if TCP in out:
        del out[TCP].chksum
    out = IP(bytes(out))  # forces IP/UDP/TCP checksum recomputation
    return out
```

## Risks, tradeoffs, open questions

- **B may be unmeasurable on this corpus.** A length-prefixed framing is a synthetic C2 design, and the Stratosphere captures are HTTP and IRC. Task 3 checks this before task 8 rather than after. If no `length2` flow exists, B ships as unit-test-only and that must be stated, not hidden behind a 0/16.
- **The framing guess could be wrong.** `detect_framing` defaults to `http`. A misclassified IRC flow would make A look like it evades for the wrong reason. Verify by printing the detected framing for a handful of flows before trusting task 8.
- **A is only defined for HTTP.** The current implementation pads any stream containing `\r\n\r\n`. On an IRC flow that is the wrong transformation, and the semantics bar should reject it. That rejection is the test that the bar works; do not weaken it to make A look better.
- **Padding shifts the pattern, so A may not survive a defender that inspects reassembled streams.** `policy first` inspects the first fragment only, which is why stream-layer padding works here at all. A `policy last` or stream-inspecting defender may see through A. Do not claim A is strong in general from one config.
- **The `depth:8` finding is corpus-specific.** These are the rules that fired on 80 flows from 2 captures. A ruleset with different depths would rank A and split differently.
- **Open:** once A evades, the honest question becomes whether PPO can exploit the extra axis or still loses to greedy, as it did before (704 vs 149 queries). Task 8 answers whether there is anything to learn; it does not answer that. That needs a re-run of `train_hidden_defender_ppo.py` and `baseline_hidden_defender.py`, which is a follow-up, not this plan.
