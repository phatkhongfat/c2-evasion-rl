      P2  len(ttls) >= 3 and std(ttls) > 15        -> detected

  MEASURED — the enhanced env is NOT a full fix. The packet list reaches the
  verdict, but the ACTION-SPACE CLAMP makes the TTL rules unreachable:
    * packet_modifier.apply_actions clamps ttl_delta to [-10, +10] (:47)
    * base_ttl = 64 (PacketModifier.__init__ default; envs use the default)
    * => reachable TTL range is exactly [54, 74]
    * P1 needs ttl < 10            : min reachable 54   -> UNREACHABLE
    * P2 needs std(ttl) > 15       : max reachable 10.00 -> UNREACHABLE
    * P5 needs min(ttl) < 20       : min reachable 54   -> UNREACHABLE
  Empirically, the strongest TTL action available (alternating +10/-10 on every
  packet, giving std = 10.00) still returns "EVADED" from the enhanced replica.
  By contrast the same rules fire correctly when handed out-of-range metadata
  by hand: ttl=5 -> "P1: Low TTL (<10)"; [20,90]*5 -> "P2: TTL variance
  (std=35.0)". So the rules are correct and the clamp is what kills them.

  NET: enhanced env re-enables frag (dim 1) and overlap (dim 3); TTL (dim 0)
  is dead in BOTH envs. The action space is effectively 1-dim in
  packet_level_env.py and 3-dim (of 4) in enhanced_packet_level_env.py.

  REWARD-SHAPING DIFFERENCE (secondary finding, same trace):
  packet_level_env.py checks detection EVERY step and terminates on first
  detection; enhanced_packet_level_env.py only checks detection at termination
  (env.step:94-113, `if terminated:` ... `else: reward = -0.1`). With a
  do-nothing policy on a 10-packet TCP flow:
      PacketLevelEnv        : 7 steps, rewards [-0.1 x6, -1.0],  detected=True
      EnhancedPacketLevelEnv: 10 steps, rewards [-0.1 x9, +10.0], detected=False
  So the enhanced env can only ever reward the TERMINAL state — an agent gets
  no per-packet feedback, and frag/overlap are evaluated only once at the end
  against the full packet list. That makes frag/overlap learnable in principle
  but with a single, sparse terminal signal.

TASK 2.4 — DOES THE BUG BLOCK LEARNING?
--------------------------------------------------------------------------------
  NO. A 4-dim action space with 1 live dim still yields a non-zero gradient, so
  PPO converges and the agent beats random (+10.67pp on >=10-packet flows, per
  the committed reports). The bug does not prevent convergence; it CAPS THE
  CEILING: with only padding reaching the reward, and padding's spread at 0.02
  on the real pool, the reachable policy improvement is bounded by an
  essentially inert signal. Consistent with the skill's note that the binding
  constraint is the environment's action->reward coupling, not the training
  budget — more training on this env cannot help.

TASK 3.1 — FRONTIER SOLVER OUTPUT FORMAT (snort_validation/frontier_exact.py)
--------------------------------------------------------------------------------
  The solver's unit of decision is a per-flow MASK, not a trajectory.

  Algorithm (exact, per-flow, no joint search):
    - score() judges each flow independently, so the global minimum is the SUM
      of per-flow minima (frontier_exact.py:1-11). No sequential plan is built.
    - progressive deepening over k = 1..MAX_K: test every k-SUBSET of the flow's
      reachable payload packets (itertools.combinations, :87) and stop at the
      first k that evades. A subset, by construction, is an unordered SET.
    - on a hit it records the winning subset: best_mask[fi] = list(combo) (:117),
      and OPTIMAL_MASK[fi] = that list (:120).

  EMITTED ARTIFACT — labels/oracle_<capture>.json (frontier_exact.py:149-158):
    keys = [capture, n_flows, control_mean_corrupt, control_evaded,
            unevadable, optimal_mask, min_k]
      "optimal_mask": { "<flow>": [pkt_idx, ...] }   <- SET of packet indices
      "min_k":        { "<flow>": k }                 <- its cardinality
    Verified by loading the file: optimal_mask values are Python lists of ints
    (e.g. flow 5 -> [0,3,6,9]); min_k values are ints. There is NO ordering
    field, NO step index, NO action-per-timestep trace. The solver never emits
    a sequence an autoregressive agent could imitate.

  => The target is a binary mask over the packet slots. This is exactly the
     output shape a set-encoder produces and exactly what a per-packet
     left-to-right policy cannot express.

    the binding metric — the end-to-end control gate is.

    flow 17    -> [0,1,2]

    flow 23    -> [14,19]     (late, far apart)
  A left-to-right autoregressive agent commits a decision at slot 0 before it
  has any basis to know that slot 3 (or 9, or 19) must ALSO be corrupted, and it
  cannot revisit. This is a coordination requirement across non-adjacent slots,
  which is a SET problem.

  CONTRAST — 20110811 is degenerate and must not drive the decision:
    its optimal mask is [3] for 23/24 flows and [3,13] for one. A single fixed
    index dominates, so ANY per-packet scorer (and even a constant) reproduces it.
    This is why the per-packet MLP "beats" there (24/24 @ 1.42) yet "loses" on
    20110819. The architecture question is decided on 20110819 alone.

TASK 3.4 — DECISION MATRIX
--------------------------------------------------------------------------------
  | Approach                      | Obs unit       | Decision unit      | Can coordinate k=2-4 scattered sets? | Matches solver? | Complexity |
  |-------------------------------|----------------|--------------------|--------------------------------------|-----------------|------------|
  | Autoregressive (current)      | one packet     | one action/step    | NO — independent per slot, no memory | NO              | Low        |
  | Set-encoder (self-attention)  | full packet set| corruption mask    | YES — joint, permutation-invariant   | YES             | Medium     |
  | Hybrid (AR + recurrent memory)| one packet     | action + carry     | partially — indirect, still serial   | NO              | Medium     |

  Evidence per row:
    - Autoregressive: PacketPolicy scores each slot with the same MLP
      independently; measured END-TO-END 14/24 @ 2.35 -> LOSES the gate.
    - Set-encoder: emits a per-slot logit conditioned on the WHOLE packet set,
      so slot 0's decision can depend on slots 3/6/9. This is the only family
      whose decision unit equals the solver's optimal_mask.
    - Hybrid: can carry state, but still decides serially and never sees the
      future slots at decision time -> cannot commit to {0,3,6,9} as a unit.

RECOMMENDATION: SET-ENCODING.
--------------------------------------------------------------------------------
  Rationale:
    1. The frontier solver emits per-flow MASKS (binary/set over packet slots),
       not trajectories. The decision unit of the target == the decision unit of
       a set-encoder. There is nothing sequential to imitate.
    2. On 20110819 the optimum is a scattered set: 18/23 flows need k>=2 and
       17/23 masks are non-contiguous ({0,3,6,9}, {1,7,9}, {14,19}). A per-packet
       autoregressive policy has no mechanism to select slot 0 AND slot 3 jointly.
    3. The current policy is literally a shared per-packet MLP (no cross-slot
       term) — it CANNOT represent a joint set. The measured result confirms it:
       83% exact-mask match but 14/24 end-to-end vs control 23/24 -> loses.
    4. The single-feature signal is degenerate (top-5 all 82% < 87% index-0
       baseline), so more per-packet feature columns will not rescue the
       architecture; the coupling is the missing ingredient.
    5. The planned semantic observation (which rule SIDs fire) is set-level by
       nature — a rule fires if ANY packet in the flow matches — so it composes
       naturally with a set-encoder and not with a serial policy.

  Concrete design (minimal, to be validated by the BC gate below):
    - Input: per-packet feature matrix (32, MAX_PKT_FEAT=15) from packet_features().
    - 2-4 layers of self-attention (d_model 64, permutation-invariant, no
      positional encoding by default; optionally a learned slot embedding), a
      mask over padding slots.
    - Output head: per-slot logit -> Bernoulli mask (identical output shape to
      the solver's optimal_mask, so BCE toward the oracle is direct).
    - Constraint note: mask cardinality should be free (no fixed k) so the model
      can learn k=1 for easy flows and k=4 for the stride-3 flows.

GATE FOR THE BC BASELINE (must pass BEFORE any full RL)
--------------------------------------------------------------------------------
  Purpose: behaviour cloning is only worth attempting if the FEATURES can express
  the optimal mask. If a supervised net cannot hit the oracle masks, RL cannot
  either, and the bottleneck is feature quality — not the policy architecture.

  Procedure:
    1. Load exact optimal masks from labels/oracle_botnet-capture-20110819-bot.json
       (and ...-20110811-neris.json for regression).
    2. Train TWO supervised baselines with BCE toward the oracle mask, identical
       features, identical split:
         (a) per-packet MLP  = the current PacketPolicy head (independent slots)
         (b) set-encoder     = self-attention over the full packet set (joint)
       Both on the 15-feature packet matrix. This isolates ARCHITECTURE from
       FEATURES: if (b) > (a), set-encoding is the lever; if (b) == (a), it is not.
    3. Eval — the acceptance test is END-TO-END, not mask-match: sample the
       predicted mask, play it through the real resident Snort service, and grade
       with snort_validation/control_gate.py::policy_beats_control
       (beats == policy_evaded >= control_evaded AND policy_mean_corrupt <
       control_mean_corrupt).
    4. Seed >= 5 runs (harness_variance.py shows a single batch on a used Snort
       instance is not comparable — always use a fresh instance per run).

  NUMERIC GATE (both captures must hold; 20110819 is the decisive one):
    20110819-bot : control = 23/24 evaded @ mean 10.50 corruptions.
                   PASS  <=>  evaded >= 23/24  AND  mean_corrupt < 10.50
                               (beats=True), sustained across >= 5 seeds.
                   (Current per-packet MLP: 14/24 @ 2.35 -> FAIL, as expected.)
    20110811-neris: control = 24/24 @ 2.88. Must not regress:
                   PASS  <=>  evaded == 24/24  AND  mean_corrupt < 2.88.
                   (Current per-packet MLP: 24/24 @ 1.42 -> already PASS.)

  DECISION RULE:
    - If (b) passes 20110819 and holds 20110811 -> architecture hypothesis
      confirmed. Proceed to full RL (mask policy, e.g. PPO over the Bernoulli
      mask) and then to semantic obs (rule SIDs) + multi-capture training.
    - If (b) passes but only barely (e.g. 23/24 @ 10.4) -> treat as fragile;
      add semantic obs BEFORE scaling RL, since the residual gap is feature-side.
    - If (b) ties or loses on 20110819 -> the architectural hypothesis is WRONG;
      set-encoding is not the bottleneck. Return to FEATURE ENGINEERING (semantic
      rule-SID observation) rather than training a larger model.
    - Do NOT start full RL until a BC baseline clears the gate: RL over a
      mask space it cannot express just reproduces the per-packet ceiling.

  4. RECOMMENDATION: SET-ENCODING (self-attention over the packet set ->
